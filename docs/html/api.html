libclamav C API

The public interface for embedding the ClamAV scan engine. Operations below are grouped swagger-style: a category chip, the signature, then parameters and responses. All functions return cl_error_t unless noted; CL_SUCCESS means the call worked.

Canonical flow: cl_init() → cl_engine_new() → cl_load() → cl_engine_compile() → scan → cl_engine_free().

Engine lifecycle

INITcl_error_t cl_init(unsigned int initoptions)once per process

Initializes global library state (crypto, locale, rand). Must be called exactly once before any other API. Pass CL_INIT_DEFAULT.

CL_SUCCESS — library ready · CL_E* — initialization failed; do not proceed.

CREATEstruct cl_engine *cl_engine_new(void)new engine instance

Allocates a scan engine with default settings and a reference count of 1.

engine* — configure and load databases into it · NULL — allocation failure.

CONFIGcl_engine_set_num / get_num · set_str / get_strtune limits & options

Typed getters/setters keyed by enum cl_engine_field. Numeric fields include CL_ENGINE_MAX_FILESIZE, CL_ENGINE_MAX_SCANSIZE, CL_ENGINE_MAX_RECURSION, CL_ENGINE_PCRE_MATCH_LIMIT; string fields include CL_ENGINE_TMPDIR and CL_ENGINE_PUA_CATEGORIES.

ParamTypeDescription
enginestruct cl_engine *Target engine (before cl_engine_compile)
fieldenum cl_engine_fieldWhich setting
num / strlong long / const char *New value (setters)

CL_SUCCESS · CL_EARG — wrong field type or null engine.

COMPILEcl_error_t cl_engine_compile(struct cl_engine *engine)finalize before scanning

Builds the matcher automata from all loaded signatures. Required after cl_load() and before any scan; the engine's settings are frozen afterward.

CL_SUCCESS — engine scannable · CL_EMEM / CL_EMALFDB — compilation failed.

REFCOUNTcl_engine_addref · cl_engine_freeshared ownership

cl_engine_addref() increments the reference count for multithreaded sharing; cl_engine_free() decrements and destroys the engine when it reaches zero. cl_engine_settings_copy / _apply / _free snapshot settings across engine reloads.

Scanning

All scan entry points take a struct cl_scan_options with four bitfields — general, parse, heuristic, mail, dev — e.g. CL_SCAN_GENERAL_ALLMATCHES, CL_SCAN_PARSE_ARCHIVE, CL_SCAN_HEURISTIC_ENCRYPTED_ARCHIVE.

SCANcl_scanfile(path, &virname, &scanned, engine, options)scan by path
ParamTypeDescription
filenameconst char *Path of the file to scan
virnameconst char **Out: detection name when a signature alerts
scannedunsigned long *Out (optional): data scanned, in CL_COUNT_PRECISION units
engineconst struct cl_engine *Compiled engine
scanoptionsstruct cl_scan_options *Scan option bitfields

CL_CLEAN — no detection · CL_VIRUS — detection, name in virname · CL_E* — scan error.

SCANcl_scandesc(desc, filename, &virname, &scanned, engine, options)scan an open fd

Same contract as cl_scanfile() but reads from an already-open file descriptor; filename is metadata only (may be NULL). This is what clamd uses for FILDES.

SCANcl_scanmap_callback(map, filename, &virname, &scanned, engine, options, context)scan memory

Scans a cl_fmap_t built from a buffer or handle — no file on disk required. The context pointer is passed through to every callback fired during the scan.

SCAN-EXcl_scanfile_ex · cl_scandesc_ex · cl_scanmap_exextended verdict API

Extended variants that report results through a cl_verdict_t and expose per-layer detail via the cl_scan_layer accessors (cl_scan_layer_get_fmap / _get_type / _get_recursion_level / _get_last_alert / _get_attributes…), pairing with the cl_engine_set_scan_callback() mid-scan hook.

In-memory maps (cl_fmap)

MAPcl_fmap_open_memory(start, len) · cl_fmap_open_handle(...)wrap data for scanning

cl_fmap_open_memory() wraps an existing buffer; cl_fmap_open_handle() wraps an arbitrary handle with a user-supplied pread-style callback so libclamav can page data on demand. Companion accessors: cl_fmap_set_name/_set_path, cl_fmap_get_size/_get_fd/_get_data, hash helpers (cl_fmap_set_hash / _get_hash / _have_hash), and cl_fmap_close() to release the map.

Callbacks

Registered per-engine; each receives the scan's context pointer. A callback's return value can veto or alter the verdict for its layer.

Databases & updates

LOADcl_load(path, engine, &signo, dboptions)load signatures

Loads a database file or a whole directory (see cl_retdbdir() for the default). signo accumulates the signature count. dboptions: CL_DB_STDOPT, CL_DB_BYTECODE, CL_DB_OFFICIAL_ONLY, …

CL_SUCCESS · CL_EMALFDB / CL_EOPEN — malformed or unreadable database.

CVDcl_cvdhead · cl_cvdparse · cl_cvdverify(_ex) · cl_cvdunpack(_ex) · cl_cvdgetagecontainer inspection

Read a CVD's 512-byte header (version, signature count, build time), verify its digital signature (the _ex forms use the newer certs-directory external-signature scheme), unpack contents, or check database age.

WATCHcl_statinidir · cl_statchkdir · cl_statfreedetect db changes

Snapshot a database directory and later test whether it changed — the mechanism behind clamd's self-check/reload cycle.

Return codes (cl_error_t)

CodeMeaning
CL_SUCCESS / CL_CLEANOperation succeeded / no detection
CL_VIRUSSignature alerted; name via virname or callback
CL_EMEM · CL_EOPEN · CL_EREAD · CL_EWRITEResource and I/O failures
CL_EMALFDB · CL_EUNPACK · CL_EPARSEBad database / unpacking / parsing errors
CL_EMAXREC · CL_EMAXSIZE · CL_EMAXFILESEngine limit reached (usually treated as clean)
CL_BREAKScan aborted by a callback

Use cl_strerror(code) for a printable message and cl_retver() for the library version string.

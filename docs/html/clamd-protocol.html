clamd Wire Protocol

clamd speaks a plain-text command protocol over a TCP or Unix-domain socket. Each command below is documented like an API endpoint: category chip, command line, request semantics, and response format.

Conventions

  • Terminate commands with a newline (\n) or NUL (\0). Prefix with z for NUL-delimited or n for newline-delimited responses — e.g. zSCAN file\0. Prefixed form is strongly recommended so filenames with newlines can't break parsing.
  • Path-taking commands require the path to be readable by the clamd process — clients on remote hosts should use INSTREAM instead.
  • Scan replies follow <path>: <result>, where result is OK, <Signature.Name> FOUND, or <message> ERROR.

Scan commands

SCANSCAN <path>scan file or directory

Scans a file or recursively a directory; stops at the first detection.

→ zSCAN /home/user/eicar.com\0
← /home/user/eicar.com: Win.Test.EICAR_HDB-1 FOUND
SCANCONTSCAN <path>don't stop on detection

Like SCAN, but continues through the rest of the tree after a detection, reporting one line per file.

SCANMULTISCAN <path>parallel scan

Distributes the files under path across clamd's thread pool (thrmgr) for parallel scanning. Not allowed inside an IDSESSION.

SCANALLMATCHSCAN <path>report every signature

Scans with all-match mode enabled so every matching signature is reported for each file, not just the first.

Streaming & descriptor passing

STREAMINSTREAMscan data sent over the socket

Client streams file content in chunks: each chunk is a 4-byte big-endian length followed by that many bytes; a zero-length chunk ends the stream. Exceeding the daemon's StreamMaxLength gets INSTREAM size limit exceeded ERROR and disconnect.

→ zINSTREAM\0
→ [00 00 10 00][4096 bytes] … [00 00 00 00]
← stream: Eicar-Signature FOUND
STREAMFILDESpass an open fd (Unix socket only)

Sends a file descriptor via SCM_RIGHTS ancillary data; clamd scans the descriptor directly. Fastest local option — no copy, no path-permission issues.

Control

CTRLPINGliveness check

Replies PONG. Used by clamdscan and health checks.

CTRLRELOADreload databases

Reloads the signature databases (concurrently with ongoing scans, since the engine is refcounted). Replies RELOADING.

CTRLSHUTDOWNstop the daemon

Performs a clean shutdown, closing sockets and finishing in-flight work.

CTRLSELFCHECKtrigger db freshness check

Runs the periodic database self-check (normally driven by SelfCheck interval) immediately.

Introspection

INFOVERSIONengine + db version 
← ClamAV 1.x.x/27xxx/<db build date>
INFOVERSIONCOMMANDScapability discovery

Returns the version plus a pipe-separated list of supported commands — use this for feature detection instead of parsing version numbers.

INFOSTATSthread-pool & queue state

Multi-line report of pool threads (live/idle/max), queue length, and memory stats, terminated by END. This is what clamdtop renders.

INFODETSTATS · DETSTATSCLEARdetection counters

Reads (and resets) internal detection statistics counters.

Sessions

SESSIONIDSESSION … ENDmultiplexed connection

Opens a session in which multiple commands can be pipelined on one connection. Every reply is prefixed with a request ID: <id>: <reply>, so responses can be matched even when they arrive out of order. Within a session, only NUL-delimited (z-prefixed) commands are accepted, and SCAN/MULTISCAN-style path recursion is restricted — prefer INSTREAM and FILDES. END closes the session.

→ zIDSESSION\0 zPING\0 zINSTREAM\0[chunks] zEND\0
← 1: PONG
← 2: stream: OK
Commands not recognized, oversized command lines, or size-limit violations cause clamd to reply with an ERROR line and close the connection. Idle connections are dropped after CommandReadTimeout.
